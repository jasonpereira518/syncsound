# Decisions

| # | Decision | Alternatives | Reason |
|---|----------|--------------|--------|
| 1 | TypeScript 6.0.x | TS 7 (native) | typescript-eslint 8.x peer range is `<6.1`. |
| 2 | Packages export `.ts` source, no build step | tsup/tsc builds per package | Fewer moving parts; Next `transpilePackages`, `tsx` for server, Vitest native TS. |
| 3 | Plain Node `http` + `ws` server | Bun, uWebSockets.js | `ws` is the prompt's default; runs everywhere incl. CI/Docker. |
| 4 | `pnpm -r --parallel` for `pnpm dev` | `concurrently` | No extra dependency. |
| 5 | `apps/web/tsconfig.json` maps `zustand/vanilla` + `zustand/react` via `paths` | rename the checkout dir | TypeScript substitutes `*` of package `exports` patterns into the *whole* absolute path, and this checkout lives under `**Quick Projects`. The mapping is harmless in any other path. |
| 6 | Snap every `AudioBufferSourceNode.start(when, offset)` to the sample grid (`snapToSampleGrid`) | keep sub-sample starts | Chromium linearly interpolates fractional-sample starts → up to −2.4 dB at 11 kHz (found by the loopback-calibration E2E: a "flat" loopback measured 2.7 dB droop; 0.00 dB after the fix). Timing error ≤ 10 µs. |
| 7 | `?loopbackMic=<ms>` test mode records the device's own calibration emissions instead of the mic | fake-mic WAV (can't be time-aligned) | Lets Playwright run the full calibration wizard + real measurement code in a real browser. |
| 8 | Web store split into `store/state.ts` (zustand) + `store/roomStore.ts` (actions) | one file | lib modules write to the store without an import cycle. |
| 9 | Host auto-sends `defaultObjectsFor(channels, upmix)` per (track, channels, upmix), keeping existing positions | manual object setup | 5.1 files would otherwise be half-silent with the default L/R scene. |
| 10 | Spotify PKCE via popup (falls back to full redirect) | redirect only | Keeps the room page (and its AudioContext) alive during sign-in. |
| 11 | `expectedHeardEpochMs = timeOrigin + ctxToPerf(when) + L − (offset − trackOffset)·1000` | brief's formula | The brief double-counted auto latency in fallback mode; unit test checks devices with different latencies agree. |
| 12 | Sync-measurement tool: all devices emit device-unique chirps simultaneously once per second (`purpose: 'measure'`, slot `repeat`/`periodMs`), listener separates by matched filter, error = arrival − per-click mean | per-device sequential clicks | One recording measures true simultaneous sync; listener input latency and clock error cancel. Emitters use FULL playback compensation with a 1.5 s lookahead so the measurement reflects real playback. |
| 13 | `AudioClockMap` detects output-path latency steps (3 consecutive outliers > 6 ms agreeing within 3 ms) and shifts history onto the new regime | fixed regression window | A 44 ms output-latency step (seen in Chromium when a recorder starts; also Bluetooth profile switches) bent the regression into a −11 000 ppm slope for 16 s → clicks 30 ms off. Found by the loopback sync-measurement E2E (jitter 9.5 ms → 0.03 ms). |
| 14 | Recorder writes zeros for blocks where its input is inactive; calibration waits 1.5 s after opening the input before scheduling | — | Keeps sample index ↔ context time exact; lets the output path settle after opening a mic. |
| 15 | `?fakeCapture=tone|silent` test hook replaces getDisplayMedia with a synthetic stream | skip capture E2E | Exercises the real WebRTC mesh, receive path and DRM-silence detection headlessly. |
| 16 | Capture transport = plain RTCPeerConnection mesh (host → each device) | LiveKit SFU | No extra infrastructure; fine for small rooms (host uplink = N × ~256 kbps Opus). LiveKit recommended beyond ~8 devices (see LIMITATIONS). |
| 17 | Room UI is a fixed-viewport shell: header · Library (queue + sources) \| Stage \| Devices/Calibrate tabs · bottom player bar (Spotify layout); panes scroll internally, the page never does. Phones: one pane at a time via the bottom tab bar, player bar above it. Stage rendering/room-size settings fold into a `<details>` | long dashboard page | Everything (incl. transport) visible at once on desktop; the stage map keeps the height. |
| 18 | R1: drift control is a critically damped PI loop (Kp = 1/4 s, Ki = Kp²/4), no deadband; the integral (learned clock-rate mismatch) persists across tracks and is forgotten on output-route change | feed-forward from `AudioClockMap` slope | Self-contained in `DriftController` and needs no new plumbing. A deadband turns the integral into a limit cycle. Sim mean bias 1.48 → 0.12 ms. |
| 19 | R1: LAN clock master. Peers sync to one in-room device's raw `performance.now()` over an unordered, no-retransmit DataChannel at 10 Hz (128-sample window), and the master shares its server `ClockSync` mapping (`ClockMapping`) every 500 ms. Election: connected host, else desktop/laptop, else lowest id. | Peers sync to the master's *room-time estimate* | That estimate slews, and peers lag it (sim p95 0.95 ms). Sharing the mapping makes the WAN error identical on every device (sim p95 0.41 ms). Server clock stays the fallback whenever the link isn't ready. |
| 20 | R1: `RTC_SIGNAL` gains an optional `ch: 'capture' \| 'clock'` | A second message type | Additive; capture signaling is unchanged when `ch` is absent. |
| 21 | R1: `outputLatency` > 120 ms classifies the output as Bluetooth (in addition to the label regex) | Label only | Browsers don't expose the route, but wired/built-in outputs report ≲ 60 ms. Bluetooth jitter measurement and quick re-sync move to R3 because they extend the calibration code. |
| 22 | R2: the device `role` *is* its layout slot (L R C SL SR RL RR Sub, Full = unassigned); `scene.layout` (optional, absent = custom) picks routed vs positional mixing | Separate slot map in the scene | Role already exists, is per-device and persisted in profiles; one field instead of three disagreeing ones (role dropdown, join-order presets, objects). |
| 23 | R2: routed layouts reuse the object pipeline: `computeDeviceMix` swaps DBAP for `routedGains` (equal-power within a slot, fold-down chain C→L/R, SL→RL→L, AMB→surrounds→fronts); unassigned devices are silent there | A new channel-matrix render path in the engine | Zero engine/graph changes; bass management, EQ, delays and calibration all keep working unchanged. |
| 24 | R2: `autoAssign` fills slots by device class (desktop > laptop > bluetooth > tablet > phone, then join time) and keeps existing subs; the role dropdown stays until R5's room diagram replaces it | Auto-pick subwoofers by `bassCapable` | Promoting a laptop to "sub" would be a surprise; subs are a user choice. The dropdown now really moves sound, so it stays useful until the diagram lands. |
| 25 | R3: loudness still matches the quietest device (equal dB is guaranteed); devices > 3 dB under the median get `volumeUpDb`, shown on that device as "turn this device up, then re-tune" | Median target with up to +6 dB software boost (the plan's first idea) | The output limiter sits at −3 dBFS, so a boost compresses or clips loud material. Raising the hardware volume and re-tuning gets the same loudness cleanly. |
| 26 | R3: "Quick re-sync" = the normal calibration with chirps only (`include: ['chirp']`), ~1.1 s per device; it sends only latency (no trim/EQ/volumeUp fields) | A single-device re-measure | Relative latency needs every device's arrival as a reference; chirp-only keeps one code path. Sim: same < 1 ms accuracy as the full pass. |
| 27 | R3: calibration pauses playback when this device may control it and resumes the same track afterwards; `volume` joins `PROFILE_KEYS` | — | Music under the sweep ruins the measurement; a device's volume should survive a rejoin like its trim does. |
| 28 | R4: persistent Home: `HomeStore` (`${dataDir}/homes.json`, same debounced JSON pattern as profiles via a shared `JsonStore`) holds `{ id, ownerKeyHash, rooms[] }`. No accounts: the home id is a capability link; the 128-bit owner key is stored as a SHA-256 (no salt/KDF needed at that entropy) and doubles as JOIN `hostKey` in home rooms. Stored room ids are room codes in the same code space as temporary rooms, so JOIN-by-code and old `/room/[code]` links work unchanged; `RoomManager.get` brings a stored room up on demand, the TTL sweep only unloads it, and `Room` writes scene/settings/password hash back through `onConfig`. Home rooms keep pruned speakers' positions. Home API is HTTP (`/api/homes…`, owner key in `x-owner-key`), not WS `HOME_*` messages | WS `HOME_*` messages | A joined socket drops anything not room-sequenced (`seq ≤ lastSeq`), and the home page joins no room. Group play = one start time `T = now + max(room lead)` applied to every room via `Room.controlAt`, so all SCHEDULEs share `startRoomTime` on the shared perfClock. |
